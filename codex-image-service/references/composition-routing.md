# 批量图像工程合成策略

长图只是批量图像工程的一种交付形态。先判断最终交付语义，再决定是否允许像素融合。不要因为输入有多张图片就默认拼接。

## 路由表

| Profile | 典型需求 | 对齐 | 接缝 | 融合 | 默认产物 |
|---|---|---|---|---|---|
| `material-kit` | 一组宣传物料、电商套图、品牌系列 | 无 | 版式边界 | 无 | 独立成品 + 联系表 |
| `grid` | 九宫格、杂志拼图、非对称网格 | 无 | 网格边界 | 无 | 确定性布局 |
| `storyboard` | 分镜、漫画格、故事板 | 无 | 分镜边界 | 无 | 顺序布局 + 编号 |
| `carousel` | 小红书或社媒轮播 | 无 | 页面边界 | 无 | 独立页面 |
| `document` | PPT、信息图页面、文档配图 | 无 | 页面边界 | 无 | 页面级文件 |
| `generated-continuous` | 生成式连续长图、多屏连续插画 | 平移 | 重叠安全区 | 多频段 | 分屏 + 连续成品 |
| `panorama` | 建筑、室内、风景实拍全景 | 特征点 + 单应性 | Graph Cut | 多频段 | 全景图 + 算法报告 |
| `object-blend` | 抠图植入、局部换景、物体融入背景 | 蒙版定位 | 蒙版边界 | Poisson | 合成图 + 蒙版报告 |

## 自动选择顺序

1. 先读取用户要的交付形态，区分独立资产、确定性布局和像素融合。
2. 运行 `adaptive_compositor.py plan` 生成路由报告。
3. 布局型任务保留全部独立源图，使用 `assemble_images.py custom-grid` 或联系表；不要做特征对齐和融合。
4. 连续生成图先按接口生成，再进行平移校正、真实重叠检测和多频段融合。
5. 实拍全景使用特征点、RANSAC 单应性、Graph Cut 接缝和多频段融合。
6. 只有具备明确前景蒙版时才使用 Poisson；禁止自动猜蒙版。
7. 光流只处理水面、树叶、布料等小范围非刚性变化；检测到文字、人脸、产品或建筑硬边时禁用。
8. 任何高级算法缺少依赖、匹配点、内点率、蒙版或可信度时，停止并返工；禁止回退零重叠硬拼。

## 算法边界

- 平移校正适合尺度与透视基本不变的相邻生成图。
- 单应性适合同一平面或相机旋转产生的实拍重叠，不适合排版文字和人物近景。
- 光流可能拉扯结构，只能作为明确选择的局部校正。
- Graph Cut 负责选择低冲突接缝，不能修复完全不同的场景。
- 多频段融合处理不同空间频率的亮度和纹理差异，不能替代正确对齐。
- Poisson 会重建边界颜色，只用于有蒙版的局部植入。

## 运行时

规划和多频段融合依赖 Pillow、NumPy。特征单应性、光流、Graph Cut、全景和 Poisson 使用可选 OpenCV 运行时。脚本从 `CODEX_IMAGE_RUNTIME` 或 `~/.codex/image-runtime` 加载隔离运行时，避免污染系统 Python。高级运行时不可用时必须在报告中明确失败，不得悄悄选择更差算法。
